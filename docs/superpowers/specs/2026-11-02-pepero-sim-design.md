## 1. 무엇이고 왜 만드는가

내가 좋아하는 캐릭터 이미지를 올리면 그 **실루엣 모양의 3D 쿠키**가 만들어지고, 그 쿠키를 **마우스/손가락으로 직접 잡아 초코 통에 담가서** 나만의 빼빼로를 완성하는 웹사이트.
완성한 빼빼로는 **링크로 친구에게 보내고**, **갤러리**에서 다른 사람 작품도 구경한다. 빼빼로데이(11/11) 같은 시즌에 가볍게 만들고 공유하는 장난감.

핵심 재미는 두 가지다.
1. 내 캐릭터가 그대로 쿠키가 된다 (알아볼 수 있어야 함).
2. 초코를 **내 손으로 담근 만큼** 묻는다 (버튼/슬라이더가 아니라 직접 조작하는 손맛).

## 2. 목표 / 비목표 / 안티목표

### 목표 (v1)
- 이미지 업로드 → 실루엣 3D 쿠키 생성
- 막대 옵션 ON/OFF
- 직접 잡고 담그는 초코 딥핑 (담근 깊이만큼 코팅)
- 완성 → 닉네임 입력 → 저장 → 공유 링크
- 공유 링크 뷰 페이지 (3D 회전 + "나도 만들기")
- 갤러리 + 좋아요
- 데스크톱 마우스 + 모바일 터치 모두 지원

### 비목표 (v1에서 안 함, 단 확장 가능하게 설계)
- 로그인 / 내 작품 모아보기
- 받는 사람 이름·선물 메시지
- 토핑(아몬드, 스프링클 등)
- 쿠키 기울여 담그기
- 초코 종류 선택(화이트/딸기 등), 덧칠할수록 두꺼워지는 표현
- 원본 이미지 보관 (각인용 높이맵 같은 파생물만 저장)

### 안티목표 (이러면 기술적으로 돌아가도 실패)
- 딥핑이 사실상 "슬라이더/버튼"처럼 느껴짐 — 쿠키를 직접 쥐고 움직이는 감각이 없음
- 올린 캐릭터가 뭉개져서 무엇인지 못 알아봄
- 첫 화면이 무거워서 한참 기다림 (배경제거 AI 모델을 첫 로딩에 받는 등)
- 모바일에서 담그다가 페이지가 스크롤됨

## 4. 쿠키 만들기 (결정 사항)

### 4.1 모양 두 가지
| 옵션 | 모양 | 크기 |
|---|---|---|
| 막대 ON (A1) | 막대 **위쪽 끝에** 실루엣 쿠키가 세워져 붙음 (막대사탕 형태) | 실루엣이 막대 폭보다 넓되 작게 |
| 막대 OFF (B) | 실루엣 쿠키만 | 막대 버전보다 **크게** |

- 사용자 결정: A1 / B 형태, B는 더 크게.
- 처음에는 **초코가 하나도 안 묻은 맨 쿠키**.

### 4.2 이미지 → 실루엣 파이프라인
1. 업로드 이미지에 의미 있는 투명 영역(알파)이 있으면 그 알파를 마스크로 사용.
2. 없으면 **브라우저 안에서** 배경 제거 AI(`@imgly/background-removal` 계열)로 마스크 생성. 서버 전송 없음.
   - 모델은 업로드 시점에 지연 로딩 (첫 화면 무게에 포함 금지). 로딩 중 진행 표시.
3. 마스크 정리: 이진화 → 모폴로지(닫기/열기)로 잡티·실오라기 제거 → **가장 큰 덩어리 하나만** 사용.
4. 윤곽 추출(marching squares) → 단순화(Douglas–Peucker) → 부드럽게(Chaikin 등).
5. 너무 얇은 돌기는 둥글게 뭉갬 — 쿠키처럼 보여야 하므로 디테일보다 "알아볼 수 있는 실루엣"이 기준.
6. 결과 실루엣을 2D로 미리보기. 수동 편집 기능은 없음 (다시 올리기만).

### 4.2.1 앞면 각인 (사용자: "캐릭터를 알아볼 수 있으면 베스트")
외곽선만으로는 동그란 캐릭터가 그냥 동그란 쿠키가 되므로, 앞면에 **도장 찍은 쿠키처럼 눌린 선/면**을 넣는다.
- 마스크 안쪽 영역에서 이미지의 주요 선(눈·입·윤곽 안쪽 경계 등)을 추출: 그레이스케일 → 블러 → 에지 검출/포스터라이즈 → 잡선 제거. 세부 알고리즘은 빌더 재량.
- 결과는 **저해상도 그레이스케일 높이맵**(예: 256×256)으로 만들어, 쿠키 앞면에 노멀/변위로 음각 표현. 색은 쓰지 않음 (쿠키 색 유지).
- 높이맵은 원본 이미지가 아니라 파생물이므로 저장한다 (레시피의 `shape.relief`, Storage 파일 참조).
- 실루엣 미리보기에 각인 결과도 함께 보여줌. 각인 강도 슬라이더 1개(0 = 각인 없음) 제공 — 지저분하게 나오면 사용자가 끌 수 있게.
- 일정상 우선순위는 P1 (9장). 각인이 없어도 나머지 흐름은 완전히 동작해야 함.

- 내부 구멍(도넛 형태) 처리: 빌더 재량. 단 단순화 후 너무 작은 구멍은 메움.
- 실루엣은 **정규화된 2D 폴리곤**(단위 박스 기준 좌표)으로 다룬다. 이 폴리곤이 저장·재현의 원천.

### 4.3 3D 생성
- 실루엣 폴리곤 → 두께 있는 쿠키(Extrude + 가장자리 베벨). 쿠키 질감(구운 색, 미세한 표면 노이즈)은 셰이더/텍스처로.
- 막대: 캡슐형 원기둥. 실루엣의 **아래쪽 가장자리 중앙**에 꽂힌 것처럼 연결.
- 모든 지오메트리는 저장된 데이터(레시피)로부터 **결정적으로 재생성**되어야 함 (보기 페이지·갤러리에서 같은 결과).

## 5. 초코 딥핑 (결정 사항)

### 5.1 장면
- 화면 아래에 녹은 초코가 담긴 통. 쿠키는 그 위 공중에 세워져 있음.
- 사용자가 쿠키를 잡고(포인터 다운) 위아래(+약간 좌우)로 움직여 통에 넣었다 뺀다.

### 5.2 담그는 방향 (사용자 결정)
- **막대 ON**: 실루엣이 위, **막대 끝이 아래**. 막대부터 초코에 들어가고, 깊게 넣으면 실루엣까지 묻는다.
- **막대 OFF**: 실루엣 위쪽 가장자리를 잡고 **아래쪽 가장자리부터** 담근다. (방향은 Claude 판단)

### 5.3 코팅 규칙
- 묻는 양 = **통에 넣은 깊이만큼**. 표면 아래로 들어갔던 가장 깊은 지점까지 코팅.
- 여러 번 담그기 가능. 다시 담그면 그때 깊이까지 덮임 (더 깊으면 영역 확장, 얕으면 변화 없음). 두께 누적은 없음.
- 기울이기 없음: 쿠키는 항상 세운 채.
- 담그는 동안 좌우로 살짝 흔들리는 스프링 물리감.
- 통에서 빼면 경계선에서 초코가 1~2초 살짝 흘러내리다 굳음. 흘러내림 모양은 시드 기반 노이즈 → 저장·재현 가능.
- 코팅 경계는 일직선이 아니라 약간 물결진 자연스러운 선.
- 쿠키 위에 초코가 얹힌 느낌의 **두께감**이 보일 것 (단순 색칠 X).

### 5.4 손맛 관련 요구
- 포인터 다운 지점에 쿠키가 "붙어서" 따라와야 함 (지연·튐 없이).
- 모바일: 캔버스 위 터치 시 페이지 스크롤/줌 막기.
- 통 밑바닥 아래로는 못 내려감, 화면 밖으로 못 나감.

## 6. 저장 · 공유 · 갤러리

### 6.1 저장 데이터 = "레시피" (확장성의 핵심)
메시나 이미지가 아니라 **재현에 필요한 레시피 JSON**을 저장하고, 모든 화면은 레시피로 3D를 다시 그린다.

```ts
type PeperoRecipe = {
  schemaVersion: 1;
  shape: {
    silhouette: { outer: [number, number][]; holes?: [number, number][][] }; // 정규화 좌표
    thickness: number;
    relief?: { heightmapUrl: string; strength: number }; // 앞면 각인 (없으면 매끈한 면)
  };
  base: {
    kind: 'stick' | 'none';        // 이후 'double-stick' 등 확장
    cookieFlavor: 'plain';          // 이후 'cocoa' 등
  };
  coatings: Array<{                 // 딥핑 1회 = 1 레이어. 순서 = 적용 순서
    type: 'milk-choco';             // 이후 'white', 'strawberry' 등
    plane: { normal: [number, number, number]; offset: number }; // v1은 normal 고정(세로축). 기울이기 확장 대비 평면으로 저장
    edgeSeed: number;               // 물결 경계·흘러내림 재현용
  }>;
  toppings: [];                     // v1 비어 있음. 이후 { type, position, normal, ... }
};
```
- v1에서 연속된 같은 종류 코팅이 더 얕으면 레이어를 추가하지 않아도 됨 (최적화는 빌더 재량). 단 **데이터 구조는 레이어 배열**을 유지.
- 렌더러는 `schemaVersion`으로 분기. 구버전 레시피는 영원히 열려야 함.
- **원본 이미지는 저장하지 않음** (저작권·용량·개인정보). 폴리곤과 각인 높이맵만.

### 6.2 백엔드 (Supabase)
- 테이블 `peperos`: `id`(짧은 공유용 slug), `nickname`, `recipe`(jsonb), `thumbnail_url`, `like_count`, `created_at`.
- 썸네일: 완성 시 클라이언트에서 3D 캔버스를 PNG로 캡처해 Storage 업로드 → 갤러리 그리드와 링크 미리보기(OG 이미지)에 사용.
- 좋아요: 로그인 없음. 증가는 RPC(서버 함수)로만. 브라우저 단위 중복 방지(localStorage)는 "대충 막기" 수준으로 충분.
- 쓰기 보호: RLS로 insert만 허용, update/delete 불가. 닉네임 길이 제한(예: 20자). 레시피 크기 상한(폴리곤 점 개수 상한).
- 확장 대비: 나중에 로그인을 붙일 때 `owner_id`(nullable) 컬럼만 추가하면 되도록 설계.
- **갤러리 공개 여부** (Claude 판단): 완성 단계에 "갤러리에 공개" 체크박스, 기본 ON. `is_public` 컬럼. OFF면 링크로만 열람 가능, 갤러리 목록 제외.
- **문제 작품 내리기** (Claude 판단): `hidden` 컬럼(기본 false). 관리자가 Supabase 대시보드에서 수동으로 `hidden=true` 처리 → 갤러리·보기 페이지 모두 비노출. 신고 버튼·관리자 화면은 v1 비목표. 닉네임은 간단한 금칙어 필터만.
- 썸네일은 클라이언트 캡처 업로드를 유지하되, Storage 정책으로 이미지 타입·크기(예: 512px, 300KB) 제한.

### 6.3 페이지
- `/` 만들기, `/p/[id]` 보기, `/gallery` 갤러리.
- `/p/[id]`는 OG 메타태그(제목·썸네일) 서버 렌더 → 카톡/메신저 링크 미리보기에 빼빼로가 보임.
- 공유: 링크 복사 + 모바일은 Web Share API.

## 8. 확장성 원칙 (사용자 요청: "확장성을 고려해")
v1에 기능은 넣지 않되, 아래가 **코드 구조 변경 없이 추가**되도록 한다.
- **레시피 = 단일 진실 원천**: 만들기·보기·갤러리·썸네일 모두 같은 `renderRecipe()` 경로 사용.
- **플러그형 레지스트리**: 쿠키 베이스(`base.kind`), 코팅 종류(`coatings[].type`), 토핑(`toppings[].type`)은 각각 "타입 → 지오메트리/머티리얼 정의" 레지스트리로 관리. 새 초코 = 레지스트리 항목 1개 추가.
- **딥핑 = 평면 기반**: 코팅 영역을 "세로 높이"가 아니라 "평면 아래"로 계산 → 기울이기 기능 추가 시 normal만 바꾸면 됨.
- **편집 단계 분리**: 만들기 흐름을 `업로드 → 모양 → 딥핑 → (토핑) → 완성` 단계 배열로 구성 → 토핑/메시지 단계 끼워넣기 쉽게.
- **입력 추상화**: 마우스/터치를 하나의 포인터 드래그 레이어로 → 이후 기울이기(두 손가락 회전 등) 제스처 추가 용이.
- DB는 `owner_id`, `recipient_name`, `message` 등을 나중에 nullable 컬럼으로 추가 가능.
